# CLAUDE.md

SeatedCapeFix: a client-side BepInEx plugin (net462) that stops capes (and other cloth) from hanging through the seat when a player sits: chairs, benches, a ship's helm, sleds and carts with seats, saddles. User docs: README.md.

## The bug and the fix

Capes are MagicaCloth2 cloth (`VisEquipment.SetupCloth`). Cloth collides only with the colliders in its `colliderCollisionConstraint.colliderList`, which the game fills with the body's capsules (`VisEquipment.m_clothColliders`, shared by every cloth on the player whose own list is empty). The world is never in that list, so a sitting player's cape falls straight through the seat. The game's `Character.ResetCloth` (called on attach/detach/teleport) only resets legacy Unity `Cloth` components, so it does nothing for MagicaCloth capes.

`src/CapeSeat.cs` is a component on every player (local and remote, added in `Player.Awake`). While `Player.IsSitting()` (the animator's `sitting` tag, so it works for other players too) it probes in the player's own space (the seat's attach point places and turns the player, so up is the seat's up on a rolling ship) and gives every cloth on the player a support, re-probing every 0.5 s:

- the seat: first surface up to 0.5 m under the hips bone (none: `Guess`, one capsule edge just behind the hips at hips - 0.12);
- behind the hips in 5 cm steps: surface rays from 1 m above (a ray that starts inside a collider misses it) plus one level ray back at seat + 0.12 (thin back boards fall between samples); each 10 cm row also measures its width to the sides;
- `Drop` (the surface falls away, or the floor narrows under 0.4 m like a karve's stern): side to side capsule rows (r 0.15, 10 cm apart: an almost flat top), the last one's back at the edge, so the cape lies on the seat and falls over the edge;
- `Wall` (a wall 0.3 m or more behind) / `Floor` (the floor goes on): planes, the floor and the wall. Planes push to one side, so cloth that fell through the floor while the player sat down (before the sitting state) comes back up; capsules push what's below their axis further down, which is why floors aren't capsule rows;
- hull (`hull` in `Info`): when walls rise on both sides of the floor (a karve's stern narrowing behind the helm, which `Drop` used to treat as a seat edge, so a long cape fell through the hull), two more planes are least-squares fitted to points on the side walls (two heights per row) and added to the floor + wall planes; a plane closer than 0.15 m to the hips isn't used;
- `Backrest` (a wall closer than 0.3 m: chairs, thrones): nothing. Squeezed in front of the backrest the cape has no room and pokes out under the seat; behind it (vanilla) it's hidden best.

**Cost** (measured 2026-11-03, `probetime`/`perf`/`frametimes`): a probe is 30-130 µs native (WinHorse), 60-210 µs on the Mac under Rosetta, and allocates nothing. Kept cheap without changing what it finds: re-probes only while the player is on screen (body or cloth `isVisible`; probed at once when back in view), at most one re-probe per frame for all players, none for a player without cloth; a row's width is measured fully only for rows that become capsules, elsewhere only until it is known to reach MinFloorWidth (same decision, fewer rays); colliders, sizes and `SetParameterChange` are touched only when they change; `Info` is formatted on demand. The methods are compiled at load (`Plugin.PreJit`): JIT on the first sit-down cost ~10 ms. Under Rosetta newly run code is also translated on first run (a few ms once per new code path), which pre-JIT can't avoid.

Colliders are made once per player and never destroyed while listed: `ColliderManager.UpdateColliders` only drops a collider that is still alive and no longer in the list. A cloth whose own list was empty shares `VisEquipment.m_clothColliders`, so `Sync` collects changed lists and calls `SetParameterChange()` on every cloth using them. Plane normal = the plane transform's up.

Riding counts as sitting (`attach_lox`/`attach_asksvin` have the `sitting` tag) but the saddle isn't in the probe's layers, so mounts get `Guess`; no change seen on lox/asksvin. `attach_mast`, `attach_dragon`, `attach_bed` and helms without an animation aren't sitting: the fix stays off. Modded seats tested 2026-11-03 (feather cape, Mac): BoatAdditions, OdinShip, OdinHorse (it hides the cape while riding), OdinsBarrelRide (barrel: `Guess`, cape pokes through the barrel's side), FineWoodFurnitures, Balrond furniture (sofa `emote_sit`: `Backrest`), MountUpRestored, ALaCart, TogetherWeRow (rowing not reached through the harness). A culled remote cape isn't simulated: measure another player only while the camera sees them. Findings from the tests: the body colliders already cover thighs and shins (no leg clipping seen); a karve's walkable floor (`smallboat_colliders/boat.004`) is invisible and extends over the open hull behind the helm seat; the longship's helmsman sits on the deck 0.36 m under the hips bone; Winter Sled's back board is ~5 cm thick.

## Commands

Tools come from mise (`mise.toml`: dotnet 10). `VALHEIM_DIR` is `.deps`, a symlink to `../valheim-dev-harness/.deps`.

- `mise run build`, `mise run build-harness` (companion; needs valheim-dev-harness built next to this repo)
- `mise run test`: xunit (`SeatedCapeFix.Tests`, net10.0): every Harmony patch resolved the way Harmony does it and its injected parameters checked against the game (`PatchTargetTests`, from ClientPortals)
- `mise run package`: `dist/SeatedCapeFix-<version>.zip` (fails if `package/manifest.json` and `Plugin.Version` disagree; needs `package/icon.png`)
- Icon: `package/icon.svg` (hand-written cartoon SVG, dark background) → `mise x aqua:linebender/resvg@0.49.0 -- resvg --use-font-file LilitaOne.ttf -w 256 -h 256 package/icon.svg package/icon.png` (Lilita One, OFL, from google/fonts `ofl/lilitaone`)
- `uv run tools/make_images.py <shots dir> <Cinzel.ttf> [header off shot] [header on shot]`: `package/gallery/<n>-<scene>.jpg` (vanilla left, the fix right, labelled; `GALLERY` in the script picks the shots) and `package/nexus-header.jpg` (1300x372: the title on the left, on the right the karve from the game camera cut along its keel, before | after; from `kf_off_game.png`/`kf_on_game.png`) from `tools/harness/gallery.sh <prefix> <cape> <scene...>` shots (`g_<prefix>_<scene>_<cape>_<off|on>_<angle>.png`; scenes karve, long, bench, sled, cart, ground). Cinzel: `../valheim-layout-switch-focus-fix/.harness/fonts/Cinzel.ttf`

## Testing (Mac)

`VH_CHAR=CapeTester VH_WORLD=CapeTest tools/harness/mac-game.sh [extra dlls]` starts the Steam build with valheim-dev-harness, this mod and its companion in `.harness/profile` (Jotunn + WinterSled DLLs as extra arguments for the sled and cart seats); `tools/harness/mac-cmd.sh <<< '...'` sends commands. Companion: `cape` (cloth + colliders), `capeclip [label]` (rendered cape vertices under the seat / in the legs / forward under the hips; vertices hanging right at a bevelled edge count as under), `capev`, `sit [name]`, `helm`, `use SledSeat` (Winter Sled's sled/cart seat), `emote sit`, `stand`, `seat [field value]` (tunables live), `target remote|local` (the measuring commands look at another player), `probetime`, `perf [reset]`, `frametimes`, `hide`, `poke` (cloth vertices behind a collider), `fshot` (a screenshot that follows a drifting ship, with zoom), `hidebody`, `capeshots <prefix> [dist]`, `probeback`, `bones`, `rideon [name]` (tame, saddle and ride a creature), `mountcols`, `seats [filter]` (every prefab with a Chair, a helm or a saddle, mods' too), `seattest <prefab> [shot]` (spawn it, sit on each kind of its seats, measure, off/on shots). `tools/harness/regress.sh <tag>` (every seat × linen and feather cape: capeclip + poke; `CMD=../valheim-dev-harness/scripts/cmd.sh` runs it on WinHorse), `tools/harness/perf.sh` / `perf-win.sh <tag>` (probetime per seat, frametimes on/off), `tools/harness/restart-mac.sh` (quit and start again with the current builds; `EXTRA` = extra DLLs), `tools/harness/seatall.sh <tag> <cape> [land] [sea]` runs seattest over a list (mods go into `.harness/profile/BepInEx/plugins/mods/`). `tools/harness/cmp.py <shots> <scene> [views]` puts `off_*`/`on_*` shots side by side. Note `cfg` writes the config file: a run that ends with the fix off starts the next game with it off. Ship shots need the camera above the hull (`camshot x 180 25 3.5 1.2`). Compare with `cfg rgeraskin.SeatedCapeFix General.Enabled false`. Agree on turns with other sessions using the Mac or WinHorse.

**Multiplayer** (tested 2026-11-03 on a dedicated server, Mac + WinHorse clients joined with `VH_JOIN`/`VH_PASSWORD`, WinHorse through its VPN): another player's cape is simulated on the watching client, so the watcher's copy of the mod is what fixes it. Remote ground sit 44→0 vertices under the seat, remote sled rider 27→2 (Mac watching) and 21→1 (WinHorse watching), also while the sled is pulled; the colliders go when the remote player stands up.

## CI and releases

- `.github/workflows/ci.yml` (push to master, PRs, every Monday: a game update can break the build or the patch without any push here; the weekly cache key fetches the newest dedicated server): `tools/ci/fetch-deps.sh` (the dedicated server's Managed assemblies via anonymous steamcmd, MagicaClothV2 included, + BepInExPack from Thunderstore; versions in `tools/ci/versions.env`), build, tests, package (artifact `package`). Build like CI locally: `tools/ci/fetch-deps.sh <dir>` then `-p:ValheimDir=<dir>`.
- `.github/workflows/release.yml`: a tag `v<version>` makes a GitHub release with the zip and publishes with `tools/release/publish.cs` (ClientPortals') to Thunderstore and Hexium (categories in `tools/release/sites.json`; Hexium `installLocation: client`; the manifest description at most 256 UTF-8 bytes) and Nexus Mods (mod 4831, file group 8306025: the first file was uploaded by hand with the nexus-publish skill, in the layout publish.cs uploads, `BepInEx/plugins/SeatedCapeFix/` with the dll, README and CHANGELOG; every release also sends `package/nexus-description.bbcode`, keep it in step with README.md). Run by hand it is a dry run. Secrets: `THUNDERSTORE_TOKEN`, `HEXIUM_TOKEN`, `NEXUS_API_KEY`.
- To release: version in `package/manifest.json` and `Plugin.Version`, a `## <version>` section in CHANGELOG.md, commit, `git tag v<version> && git push --tags`.
- Lint workflows: `mise x aqua:rhysd/actionlint@1.7.12 -- actionlint`
